# Supplify Mobile - design skill stack for Claude Code

Last updated: 2026-11-16. Covers the skills Claude Code uses for UI, motion, and UX work on `supplify-mobile` / `supplify-mobile-ios` (Expo SDK 56, React Native 0.85, React Navigation 7, RN `Animated` + `react-native-gesture-handler` + `expo-haptics`).

Entry point for any screen work: the project skill `supplify-mobile-design` (`.claude/skills/supplify-mobile-design/SKILL.md`). It routes to everything below and lists the rules that do not apply to this codebase.

## 2. How Claude invokes them

- Automatic: each skill's description triggers it when a task matches. `review-animations`, `break-ui`, and impeccable's sub-commands are user-invocable: `/review-animations`, `/break-ui <component>`, `/impeccable critique <screen>`.
- Verified 2026-11-16: all fifteen skills above appear in the Skill tool listing of a Claude Code 2.1.302 session started from `C:/myProjects/supplify_erp`, and `break-ui` loaded its full instructions when invoked. A session started directly inside the mobile repos sees the user-scope skills but not the three project-scope ones.
- impeccable's first `context` run would download its engine binary (~`impeccable-windows-x64.exe`, sha256 pinned in `scripts/engine-checksums.txt`) into `~/.impeccable/bin/`. That has **not** been run. Until it is, the skill follows its own "launcher unavailable" path: it reads PRODUCT.md/DESIGN.md if present and continues with the markdown playbooks. `impeccable detect` (the slop detector) is unavailable in that mode; it is web-centric (JSX pattern rules) anyway.

## 4. The Supplify workflow

Ten steps, in `supplify-mobile-design`: inspect purpose -> look at the real screenshot -> name weaknesses by the eleven criteria -> define direction -> choose techniques -> implement in the existing architecture -> build on the emulator -> capture the required set -> critique the render -> fix, re-verify, document. The build and capture recipe lives in `C:/myProjects/wt/rebuild.sh` and the round's `cap.sh` (JDK 17, short-path sandbox `C:/w/a`, embedded JS bundle; Metro and Expo Go cannot log in because of the Keycloak redirect URI).

Compiling code is not evidence. Only the screenshot is.

## 5. Compatibility and security notes

- **impeccable** 4.9.2 ships as a plugin with `SessionStart`, `PostToolUse(Edit|Write)` and `Stop` hooks that execute a downloaded native binary on every edit. In this monorepo that would run on API, auth, and migration edits too. The hooks were deliberately not installed; the skill folder was copied by hand. If you want the detector later: `npx impeccable install --scope=project` from the mobile repo only, and accept the hook there, not in the ERP root. `/impeccable init` runs an interactive interview that writes `PRODUCT.md`/`DESIGN.md` to the repo root; do not run it in `supplify_erp` without deciding where those files belong.
- **Stale permission entries** in `~/.claude/settings.json` still allow `node .../impeccable/scripts/context-signals.mjs` and `detect.mjs`; those scripts no longer exist (harmless, can be removed).
- **Skill content is prompt, not code.** Emil's skills and the Expo skills contain no scripts. `react-native-best-practices` and `expo-*` include shell snippets in their references; they are documentation, reviewed before use.
- **No runtime dependency changed.** No package was added to either mobile repo. The skills recommend Reanimated, Worklets, `@expo/ui`, Lottie, Skia, FlashList, Legend List, keyboard-controller - every one of these is a decision, not a side effect of installing a skill.
- **Web-specific skills** (`apple-design`, `gestures`, `animation-vocabulary`, `web-design-guidelines`, `frontend-design`, parts of `impeccable`): the principles transfer (frequency gate, ease-out on entry, interruptible springs, 1:1 tracking, spatial consistency, one focal element, no all-caps labels everywhere). The code does not: CSS transitions, Motion/Framer, Vaul, `touch-action`, `@media (hover)`, `transform-origin`, `clip-path` have no RN equivalent or a different one.
- **Windows:** `npx skills add` needs `--copy`; the skills CLI prints an npm `EBADENGINE` warning on Node 20 that can be ignored.

## 6. Recommended mobile animation techniques (current stack)

| Need                                   | Technique                                                                                                                                                               |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Press feedback                         | scale 0.97-0.98 in ~110ms on pressIn, spring back on pressOut, `useNativeDriver: true`; haptic only for commits, not taps                                               |
| Reveal of a priority surface           | opacity 0->1 + translateY 8->0, 180-220ms, `Easing.out(Easing.cubic)`; once per mount, never per scroll                                                                 |
| Changing numbers                       | short crossfade (fade out 90ms, fade in 140ms), tabular figures so width does not jump                                                                                  |
| Sheets                                 | `Easing.bezier(0.32, 0.72, 0, 1)`, ~300ms; drag with gesture-handler, spring back seeded with velocity, dismiss on distance OR velocity                                 |
| Selection controls / segmented filters | animate only the indicator (absolute, childless, so `width`/`translateX` is cheap), 150-200ms                                                                           |
| Quantity steppers                      | no animation on the digit; `Haptics.selectionAsync()` per step, visual state change immediate                                                                           |
| Success moments                        | one orchestrated 400-600ms sequence (icon scale from 0.9 + opacity, then label), `Haptics.notificationAsync(Success)` on the same frame, never blocking the next action |
| Loading -> content                     | skeleton to content crossfade; never show empty state while the first load resolves                                                                                     |
| Reduced motion                         | `useReducedMotion()`: keep opacity/colour, drop translation/scale/overshoot                                                                                             |
| Screen transitions                     | React Navigation defaults; never hand-rolled                                                                                                                            |

Not animated: tab switches, keyboard, scroll, anything 100+ times a day.

## 8. Design quality checklist

See the checklist at the end of `supplify-mobile-design/SKILL.md`. Short form: primary action above the fold at 390x844 and 360x800; one focal element; no mid-word wraps or clipped labels at 1.3x; workspace name on one line; tabular/localised numbers; every string through `copy()`/`copyCount()`; >= 48dp controls with composed labels; dark status-bar icons with scrim; no tab-root back arrow; motion purposeful, < 300ms, transform/opacity, reduced-motion path, reviewed; RTL mirrored; Android build + screenshots + README + parity entry + iOS mirror/tsc/jest + "iOS not visually verified".

## 9. Screenshot verification process

1. `C:/myProjects/wt/rebuild.sh` (builds from the worktree source, installs on `emulator-5556`).
2. Baseline captures come from the untouched HEAD build in `C:/w/b` when a before/after is required.
3. Capture with the round's `cap.sh <name>` (`adb -s emulator-5556 exec-out screencap -p`): `*-en-01-initial`, `*-en-02-scrolled`, `*-ar-01-initial`, `*-ar-02-scrolled`, `*-en-03-small-360x800`, `*-en-04-small-360x800-scrolled`, `*-en-05-font-scale-1.3`, plus any globally affected screen.
4. Read every PNG with the Read tool and critique it against the eleven criteria before fixing anything.
5. Write `design-audit/mobile/round-XX/README.md`: provenance, before/after by criterion, tokens, components, known problems, next screen.
6. Switch language through More -> Language; small phone is `wm size 864x1867`; large text is `settings put system font_scale 1.3`; always reset to `wm size 1024x2216` and `font_scale 1.0`.
7. `adb install -r` keeps the session; `adb shell install` is a different command and silently leaves the old APK running.
