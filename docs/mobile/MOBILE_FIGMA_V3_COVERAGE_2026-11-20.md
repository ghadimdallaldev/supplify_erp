# Supplify V3 mobile implementation coverage

## Baseline and architecture

The Android and iOS Expo 56 apps use the same React Native screen architecture.
The `design/figma-v3` worktrees started from Android `b00c532` and iOS
`ed2fcb4`. Both baselines include the previous Home redesign and driver audit.
The worktrees are `.worktrees/mobile-v3-android` and `.worktrees/mobile-v3-ios`
under the ERP checkout. The existing mobile `dev` worktrees remain available.

`RootNavigator` selects Restaurant, Supplier, Driver, Consumer, Admin, or the
auth/account gates from the authenticated session. Guest storefront entry is
inside the native auth stack and shares the storefront, cart, checkout, and
receipt with the authenticated Consumer application. The apps share notification,
chat, account, analytics, and state primitives where their permissions permit.

`AuthContext` and `keycloakAuth` handle hosted sign-in and registration.
`tokenStorage` uses SecureStore. `sessionIsolation` and `requestScope` scope
navigation and cached requests to the active business account. `BranchPickerSheet`
manages existing workspace and branch selection. Supplier warehouse scopes come
from the authenticated session and the existing warehouse and fulfillment
queries. API requests go through `services/api/client.ts`. TanStack Query handles
query caching, Zustand handles the separate business and public carts, and
forms use local React state and the existing mutations and validation.

The approved page is [SUPPLIFY · V3 — FLAGSHIP REDESIGN](https://www.figma.com/design/DYoom98NpoZ6VOMi2xMkPj/Untitled?node-id=120-2).
Its 92 numbered frames are inventoried below. The 15 A/B/C exploratory screen
frames are outside the implementation references. The [handoff board](https://www.figma.com/design/DYoom98NpoZ6VOMi2xMkPj/Untitled?node-id=146-2785)
also lists five unresolved destination IDs (D08, R32, R33, S25, S26). Existing
run-sheet, dispute, and shortage actions remain available where supported.

**Status.** In Progress identifies direct source work or a changed shared
control under the named route. Pending identifies remaining screen-specific
work. Backend gap identifies an interaction that depends on an unsupported
server capability. The native visual column tracks Android / iOS separately.
Of the 92 frames, 88 have source work in progress, one has a backend gap,
and three are excluded because purchasing approvals were retired.

## Source changes and implementation decisions

- Reused the shared native text, buttons, inputs, search, filters, quantity controls,
  rows, sheets, safe-area handling, adaptive layout, and motion utilities. The
  UI uses V3 colors, Inter, Manrope, IBM Plex Mono, Instrument Serif, and the
  existing IBM Plex Sans Arabic faces. Original Figma SVGs are bundled locally.
- Updated native welcome, the Restaurant and Supplier Home screens, Driver
  route progress, restaurant catalog, cart and invoice list, supplier catalog,
  and the public storefront. Product detail sheets use existing catalog fields
  and cart operations. They are presented from the existing list routes.
- The restaurant checkout confirmation uses the successful checkout result.
  Restaurant Invoices and Supplier Receivables open a shared invoice detail
  from the existing scoped endpoint. The detail links to the existing invoice
  document in the authenticated web workspace.
- Restaurant tabs follow the V3 order. Suppliers with catalog access get the
  Catalog tab. Messages remain reachable from More and existing notification
  targets, and suppliers without a Catalog tab retain the Chat tab.
- The supplier workload uses the actual open order statuses and wraps
  currency-specific totals. The available order sample is labeled. The apps
  keep hosted Keycloak sign-in, native fulfillment and tracking, real product
  images, and existing storefront and checkout authorization.
- The approved designs include presentation examples for approval deadlines,
  spend trends, warehouse capacity, maps, product photos, and dispatch estimates.
  Source work uses the available live data or keeps the existing action and state.
