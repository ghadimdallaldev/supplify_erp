# Full App Feature Audit

**Date:** 2026-05-28  
**Scope:** Restaurant, Supplier, Admin, Public/Guest, Shared/System — end-to-end (UI, API, RBAC, tier gates, tests).  
**Out of scope:** New features, redesign, tier price/limit changes, Deals/Promotions business-logic changes (unless a verified bug).

**Method:** Code review of routes (`apps/web/src/App.tsx`, `apps/api/src/server.js`), RTK API (`apps/web/src/services/api.ts`), RBAC (`route-permissions.js`, `permission-keys.js`, `role-matrix.js`), entitlements (`planLimits.ts`, `planComparison.ts`, `subscription.js`), existing audits (`docs/RBAC_FULL_APP_AUDIT.md`, `docs/BRANCHES_WAREHOUSES_AUDIT.md`, `docs/admin/ADMIN_PANEL_TABS_AUDIT.md`), and targeted test runs.

---

## Status definitions

| Status         | Meaning                                                                   |
| -------------- | ------------------------------------------------------------------------- |
| **Working**    | UI + API + permissions + data path usable; tests mostly present           |
| **Partial**    | Core flow works; missing UI, edge case, test, or honest empty/error state |
| **Broken**     | Feature exists but cannot be used correctly                               |
| **UI-only**    | UI without working backend                                                |
| **API-only**   | Backend without usable UI                                                 |
| **Missing**    | Expected capability not implemented                                       |
| **Deprecated** | Intentionally removed                                                     |
